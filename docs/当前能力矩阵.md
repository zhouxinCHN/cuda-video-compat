# 当前能力矩阵

> 更新日期：2026-11-19
> 职责：本文是项目**当前实现、验证覆盖与未闭环项的唯一状态权威**。其他文档只描述设计、复现方法或历史证据，不再维护当前状态副本。
> 证据口径：本矩阵依据仓库已归档记录整理；除明确标注目标平台外，通过项（含 2026-11-19 的 LINEAR 直出探针）均为 AMD 验证机（RX 7900 XTX / ROCm 7.2.4 / Mesa 25.2.8 / FFmpeg 7.1）上的限定结果；NPP golden 来自 NVIDIA 参考机。
> 历史记录：`evidence/` 保存各批次当时的结果与限制，不作为当前能力声明；历史记录中的“未覆盖”可能已被后续证据关闭。

## 状态定义

- **AMD-PoC 已验证**：在已归档 AMD 环境和明确测试边界内通过，不代表生产或目标平台验收。
- **部分验证**：已有实现和部分证据，但仍有明确未覆盖场景或语义缺口。
- **未闭环**：实现、对照或验收仍缺失，不得纳入支持承诺。
- **非目标**：当前 P0 明确不承诺；新增需求须重新评审范围与排期。
- **目标平台待验证**：尚无自研目标平台结果，AMD 结果不得外推。

## 统一表述口径

1. **AMD-PoC 通过不等于生产验收**：必须同时说明硬件、宿主、码流、帧数和未覆盖边界。
2. **零拷贝分层表述**：
   - “无 CPU 中转”只表示解码到 HIP 不经过 CPU；
   - “libcuda D2D=0”只表示指定计数器未观察到 CUDA D2D；
   - “严格零拷贝”要求解码输出直接作为 HIP 输入，中间没有 Vulkan 图像转换或 crop 重排。
3. **历史证据不改写**：新证据关闭旧缺口时更新本矩阵，并在必要时增加新证据链接；不把历史目录中的当时限制描述成当前结论。
4. **状态变更规则**：实现或证据变化时只更新本矩阵及对应证据。其他文档发现状态副本时，应替换为按所在目录指向 `docs/当前能力矩阵.md` 的链接。
5. **探针 ≠ 兼容层能力**：`hip-decode-20261119` 验证的是驱动数据通路（受支持格式可 linear 直出并直接导入 HIP）；兼容层 Vulkan 后端当前仍走 tiled→linear 拷贝，是否改为直出须另立实现与验收。
